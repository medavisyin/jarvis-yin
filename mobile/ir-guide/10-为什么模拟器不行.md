# 为什么模拟器不行

← [[首页]]

Android Studio **有** 虚拟 Device，而且你已经开过。缺的不是 Device，是 **默认虚拟机和这个 App 不是同一种 CPU / 内存页**。

## 你现在这台虚拟机是什么

当时识别到的是：

- 名称：`sdk_gphone16k_x86_64`
- ABI：`x86_64`（附带声明了 `arm64-v8a` 翻译）
- **16 KB 页**

APK 能装上去，一点就闪退。Logcat 核心句：

这个包只含 `arm64-v8a` 的 `libcactus.so`。x86 模拟器对不上这份库，装不上或一打开就因缺少本地库而失败。

## 三层不匹配

| 层 | 这个 App | Studio 默认模拟器 |
|---|---|---|
| CPU | 只打 `arm64-v8a` | 为了快，用电脑的 **x86_64** |
| Qwen 运行时 | 只有 arm64 的 `libcactus.so` | 没有 x86_64 的引擎 |
| 内存页 | `.so` 按 4KB 对齐 | 新镜像 **16KB**（Pixel 10a / API 37+ / `ps16k`） |

Windows 上 Intel/AMD 电脑跑模拟器，默认用 x86。这个 App 的 Qwen 运行时是给真机 ARM 准备的。

## 「我再下一个 Pixel 行不行」

再下一个普通 Device **不行**。Device Manager 现在常只推 **Pixel 10a、API 37+**，里面很多是 16KB + x86_64。

若非要虚拟机，必须同时：

1. 系统镜像选 **ARM 64 v8a**（不要 Intel x86_64）
2. 名字里 **不要** 有 `16 KB Page Size` / `ps16k`

即使下对了：在 Intel Windows 上跑 ARM 模拟器是软件翻译，开机和推理都会极慢，**不适合当日常测试**。
